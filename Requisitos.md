REQUISITOS FUNCIONAIS

RF01 - Gerenciar Disciplinas: O sistema deve permitir que o professor crie, modifique e exclua as disciplinas que estão sob sua responsabilidade.
RF02 - Criar Atividades e Provas: O sistema deve permitir que o professor crie, modifique e exclua atividades gerais, além de configurar provas e testes online.
RF03 - Compartilhar Materiais de Estudo: O sistema deve permitir que o professor faça upload de arquivos (como PDFs de leitura) e adicione conteúdos na área de videoaulas para consumo dos alunos.
RF04 - Lançar e Editar Notas: O sistema deve permitir que o professor lance, edite e salve as notas dos alunos continuamente em suas respectivas atividades e provas.
RF05 - Registrar Frequência: O sistema deve fornecer uma interface para que o professor aplique faltas, registre presenças e edite a frequência da turma ao longo do semestre.
RF06 - Responder Dúvidas e Interagir: O sistema deve permitir que o professor receba e responda dúvidas dos alunos por meio de mensagens privadas ou participe de tópicos em fóruns públicos.
RF07 - Gerenciar Prova Substitutiva: O sistema deve notificar e permitir que o professor avalie e organize o agendamento de provas substitutivas solicitadas pelos alunos.

REQUISITOS NÃO FUNCIONAIS 

RNF01 - O sistema deve garantir estabilidade contínua e não apresentar lentidão, mesmo sob um alto fluxo de acessos durante a aplicação de provas online simultâneas.
RNF02 - O sistema deve realizar o salvamento automático contínuo dos dados durante o lançamento de notas e frequências, prevenindo a perda de informações do professor em caso de queda de conexão.
RNF03 - O fluxo para o registro de frequências diárias deve ser direto e não deve exigir mais do que 3 cliques a partir da página principal da disciplina do professor.
RNF04 - A interface deve possuir um design intuitivo e simplificado, ocultando jargões ou menus excessivos, com cores de alto contraste entre o fundo e a fonte para facilitar a leitura contínua.
RNF05 - A interface deve ser plenamente responsiva, permitindo que o professor lance notas ou anexos tanto pelo computador pessoal quanto por dispositivos móveis (tablets e smartphones) sem quebrar o layout.
RNF06 - Apenas os professores vinculados oficialmente à disciplina (e gestores autorizados) devem ter permissão de acesso para editar notas, aprovar provas substitutivas e aplicar faltas.
RNF07 - O sistema deve garantir que todas as transações de dados dos professores ocorram por meio de uma integração eficiente e segura exclusivamente com o sistema legado já existente na universidade, sem envolver integrações com plataformas de terceiros não homologadas.
RFXX - Adicionar Texto Alternativo: O sistema deve permitir que o professor acrescente texto alternativo (para áudio descrição) na publicação de materiais de estudo, atividades e provas.
RFXX - Habilitar Notificações Sonoras: O sistema deve permitir que o aluno ative a emissão de alertas sonoros juntamente à notificações de atividades.
RFXX - Editar Tamanho da Fonte: O sistema deve permitir que o usuário altere o tamanho da fonte (variando do tamanho padrão de 100% até 400%).
RFXX - Alterar Tema: O sistema deve permitir que o usuário escolha entre "Tema Claro" e "Tema Escuro".


RNFXX - O sistema deve emitir um aviso para o professor sugerindo o acréscimo de texto alternativo caso algum anexo seja acrescentado à publicação (de materiais de estudo, atividades ou provas) e permitir que o professor aceite ou recuse a sugestão.
RNFXX - O sistema deve fornecer a audio descrição de textos nativos na plataforma e suporte para texto alternativo.
RNFXX - Todos os botões e ícones devem possuir a descrição da funcionalidade e/ou da imagem apresentada (ex: um ícone de "disquete" que o leitor de tela reconheça como "salvar").
RNFXX - O sistema deve se acessível a pessoas com deficiência seguindo os padrões WCAG (Web Content Accessibility Guidelines) e ARIA (Accessible Rich Internet Applications).
RNFXX - O sistema deve ser responsivo para garantir que o aumento da fonte não obstrua paineis nem sobreponha botões.
RNFXX - A interface do sistema deve possuir contraste mínimo de 4.5:1 (seguindo as diretrizes da WCAG) entre as cores de fundos e textos.
RNFXX - A interface do sistema deve apresentar símbolos e descrições da função de cada botão de ação (salvar, enviar, cancelar, apagar), não dependendo apenas de cores (ex: o botão "cancelar" deve possuir cor vermelha e ser acompanhado de um  ícone de "x" e o  texto descritivo da função "cancelar").
RNFXX - Os alertas de erro devem possuir layout específico com destaque de ícones de alerta e texto "Erro" destacado.
RNFXX - Os gráficos devem possuir texturas e paletas de cores monocromáticas com enfoque no destaque dos contrastes entre tons (contraste mínimo de 4.5:1) e testados para os diferentes tipos de daltonismo (por meio de sites ou extensões que apresentem a exibição das cores para os tipos de daltonismo e sites que apresentem o contraste).
RNFXX - O sistema deve possuir um tema escuro que atenda os mesmos padrões de contraste aplicados ao modo claro.
RNFXX - O tema claro do sistema não deve ter fundo #ffff.
RNFXX - O sistema não deve integrar animações bruscas, pop-ups luminosos ou transições com trocas de cores repentinas (telas "piscantes").
