Você é um especialista em Engenharia de Requisitos e metodologias ágeis.

Com base nas personas e no contexto do sistema fornecido, gere histórias de usuário seguindo rigorosamente boas práticas de escrita de requisitos.

### Instruções:

1. Utilize o template padrão de histórias de usuário:
   Como [papel/persona],
   Eu quero [funcionalidade],
   Para [benefício/valor].

2. Para cada história de usuário, inclua:
   - Um ID único (ex: US01, US02...)
   - A história no formato correto
   - Pelo menos 3 critérios de aceitação

3. Os critérios de aceitação devem:
   - Ser objetivos e testáveis
   - Descrever comportamentos observáveis do sistema
   - Evitar ambiguidade

4. Siga os princípios INVEST:
   - Independente
   - Negociável
   - Valiosa
   - Estimável
   - Pequena
   - Testável

5. NÃO descreva como implementar (evite detalhes técnicos).
   Foque no valor para o usuário.

6. Use as personas como base obrigatória para definir o "Como [papel]".

7. Se necessário, gere múltiplas histórias para cobrir diferentes funcionalidades.

---

### Entrada:

Personas:
[COLE AQUI SUAS PERSONAS]

Contexto do sistema:
[DESCREVA O SISTEMA OU PROBLEMA]

### Saída esperada (exemplo de formato):

US01 – Notificação de tarefas
Como aluno,
Eu quero receber notificações quando uma nova tarefa for publicada,
Para que eu não perca prazos.

Critérios de aceitação:
- O sistema deve enviar notificação em até 5 minutos após a publicação
- A notificação deve conter título, disciplina e prazo
- O usuário deve conseguir acessar a tarefa ao clicar na notificação
